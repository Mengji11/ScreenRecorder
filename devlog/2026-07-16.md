### 性能优化：停止录制卡顿

**根因分析**：`StopRecording()` → `SaveRecording()` → `SaveFramesAsVideo()` + FFmpeg 合并全部在 UI 线程同步执行。1分钟30fps录制=1800帧，每帧~6MB原始数据，全部阻塞UI。

**修复措施**：
1. **异步保存**：`StopRecording()` 立即释放UI，保存工作通过 `Task.Run()` 在后台线程执行
2. **缓冲区复用**：`SaveFramesAsVideo()` 中 `byte[] rgbValues` 从每帧 new 改为单一缓冲区复用，减少 GC 压力
3. **帧处理即时释放**：编码一帧即 `Dispose()` 该帧 Bitmap，不再等全部编码完再批量释放
4. **进度反馈**：新增 `SavingProgress` 事件，每30帧报告一次进度，状态栏显示"正在编码视频 (N/M)..."
5. **保存期间锁定UI**：新增 `IsSaving` 属性，保存期间禁用录制按钮，防止重复操作
6. **去除 Thread.Sleep**：`CleanupTempFiles` 从 UI 线程 `Sleep(500)` 改为后台线程重试删除

## Bug修复：录制视频时长比实际短

### 根因
`CaptureLoop` 中使用 `Thread.Sleep(1)` 等待下一帧，但 Windows 定时器分辨率导致实际休眠 10-15ms。同时 `CaptureFrame()` 本身也需要执行时间（水印、鼠标高亮、位图转换等）。这些因素导致实际采集帧率低于设定帧率（如设定30fps实际只采到~20fps），但 `SaveFramesAsVideo` 始终按设定帧率告诉 FFmpeg，最终视频被"压缩"到更短时长。

### 修复
- `StopRecording()` 中记录实际录制时长 `DateTime.Now - _startTime`
- 传入 `SaveRecordingBackground()` → `SaveFramesAsVideo()`
- 计算实际帧率：`actualFps = frameCount / actualDuration.TotalSeconds`
- FFmpeg 输入使用 `-r {actualFps:F2}` 替代硬编码的 `settings.FrameRate`
- 影响文件：`Services/RecorderService.cs`（StopRecording、SaveRecordingBackground、SaveFramesAsVideo 三个方法）
